PROJECT BRIEF

Build ICONSULTA, an AI-Enhanced Faculty Consultation and Student Support Management System for Mandaue City College. It replaces manual/third-party scheduling with an all-in-one, online-only platform: students book consultations with faculty, faculty run the meetings via native in-browser video calls, and an AI model automatically summarizes each session. Admins manage users and monitor system-wide analytics.

Tech Stack (required — do not substitute)
Frontend: React + TypeScript (Vite), TailwindCSS for styling, React Router for navigation, React Query (TanStack Query) for data fetching/caching.
Backend: TypeScript, implemented entirely as Supabase Edge Functions (Deno runtime) — no separate Node/Express server. Each Edge Function is a small serverless handler (e.g., book-appointment, respond-to-request, generate-summary, admin-metrics).
Database: Supabase PostgreSQL, accessed via the Supabase client SDK and Row Level Security (RLS) policies enforcing role-based access (student / instructor / admin).
Auth: Supabase Auth (email + password), with a role claim (student, instructor, admin) stored in the users table and mirrored into a custom claim or checked via RLS joins.
Realtime / Video: WebRTC for peer-to-peer audio/video, with Supabase Realtime (Postgres Changes / Broadcast channels) used as the signaling layer (exchange of SDP offers/answers and ICE candidates) instead of a separate WebSocket server.
AI Summarization: After a video session ends, an Edge Function sends the session transcript to a hosted BART summarization endpoint (e.g., Hugging Face Inference API facebook/bart-large-cnn) and stores the returned summary. Keep this behind a clean summarizeTranscript(transcript: string): Promise<string> interface so the provider can be swapped later.
Storage: Supabase Storage only if needed for profile pictures; no payment processing (out of scope).
User Roles
Student — browses faculty by department/course, requests consultations, joins video calls, views AI summaries and consultation history.
Instructor (Faculty) — sets weekly availability, approves/rejects requests, hosts video calls, reviews AI-generated summaries, views their own consultation logs.
Admin — manages all user accounts (CRUD), monitors global system status, views analytics (total/completed/online/face-to-face counts — though this system is online-only, keep the field for reporting parity), generates/exports reports.

Departments to support: SOB (School of Business), SOT (School of Technology), SOE (School of Education). Instructors belong to one department and can be filtered by course.

DATABASE SCHEMA (Supabase Postgres)

Create these tables with RLS enabled. Use uuid primary keys (Supabase convention) instead of the int PKs shown in the original ERD.

sql
-- 1. users (extends auth.users via a public profile table)
users (
  id uuid primary key references auth.users(id),
  email varchar(255) unique not null,
  name varchar(255) not null,
  role text not null check (role in ('student','instructor','admin')),
  status text not null default 'active' check (status in ('active','inactive','suspended')),
  phone varchar(20),
  profile_picture_url varchar(500),
  last_login timestamptz,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 2. student_profiles
student_profiles (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references users(id) on delete cascade,
  student_id varchar(50),
  department text check (department in ('SOB','SOT','SOE')),
  year_level varchar(20),
  major varchar(100),
  enrollment_date date,
  status text default 'active' check (status in ('active','inactive','graduated')),
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 3. instructor_profiles
instructor_profiles (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references users(id) on delete cascade,
  department text check (department in ('SOB','SOT','SOE')),
  category varchar(100),
  office_location varchar(255),
  bio text,
  specializations varchar(255),
  years_of_experience int,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 4. admin_users
admin_users (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references users(id) on delete cascade,
  permissions jsonb default '{}',
  created_at timestamptz default now()
);

-- 5. instructor_availability
instructor_availability (
  id uuid primary key default gen_random_uuid(),
  instructor_id uuid references instructor_profiles(id) on delete cascade,
  day_of_week int check (day_of_week between 1 and 7),
  start_time time not null,
  end_time time not null,
  is_available boolean default true,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 6. appointments
appointments (
  id uuid primary key default gen_random_uuid(),
  student_id uuid references student_profiles(id),
  instructor_id uuid references instructor_profiles(id),
  scheduled_at timestamptz not null,
  reason varchar(255),
  status text default 'pending' check (status in ('pending','approved','rejected','completed','cancelled')),
  mode text default 'online' check (mode in ('online')), -- online-only per scope
  video_room_id varchar(100),
  rejection_reason text,
  instructor_notes text,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 7. video_sessions
video_sessions (
  id uuid primary key default gen_random_uuid(),
  appointment_id uuid references appointments(id) on delete cascade,
  room_id varchar(100),
  start_time timestamptz,
  end_time timestamptz,
  duration int, -- minutes
  participant_count int,
  created_at timestamptz default now()
);

-- 8. appointment_summaries
appointment_summaries (
  id uuid primary key default gen_random_uuid(),
  appointment_id uuid references appointments(id) on delete cascade,
  transcript text,
  summary text,
  resolution_status text default 'ongoing' check (resolution_status in ('resolved','unresolved','ongoing')),
  generated_at timestamptz,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 9. notifications
notifications (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references users(id) on delete cascade,
  appointment_id uuid references appointments(id),
  type text check (type in ('appointment','reminder','status','system')),
  title varchar(255),
  content text,
  is_read boolean default false,
  created_at timestamptz default now()
);

-- 10. analytics_metrics (materialized/aggregated daily by an Edge Function or scheduled job)
analytics_metrics (
  id uuid primary key default gen_random_uuid(),
  date date not null,
  total_appointments int default 0,
  approved_appointments int default 0,
  pending_appointments int default 0,
  rejected_appointments int default 0,
  completed_appointments int default 0,
  student_activity_count int default 0,
  instructor_activity_count int default 0,
  avg_session_duration decimal(5,2),
  created_at timestamptz default now()
);

RLS rules to implement:

Students can only read/write their own student_profiles, appointments (where student_id = their profile), and appointment_summaries/notifications tied to their own appointments.
Instructors can read/write their own instructor_profiles, instructor_availability, and manage appointments where instructor_id = their profile (approve/reject, add notes).
Admins have full read access to all tables and write access to users, admin_users, and analytics_metrics.
CORE FEATURES TO IMPLEMENT
Auth & Onboarding
Login (email/password) and Sign Up with role selection (Student / Instructor). Instructors select their department (SOB/SOT/SOE) right after signup.
Route guards per role; redirect to the correct dashboard after login.
Student Portal
Dashboard: upcoming consultations, pending requests, completed count, quick actions (Browse Faculty, View My Consultations).
Faculty directory: filter by department and course; view instructor profile and weekly availability.
Book a consultation: pick an available slot, add a reason, submit request.
My Consultations: status tracker (pending/approved/rejected/completed), join video call button when approved and time has arrived, view AI summary after session ends.
Instructor Portal
Dashboard: pending requests, approved consultations, completed sessions, quick actions.
Availability setter: weekly recurring time-slot matrix (day + start/end time).
Requests review: approve/reject incoming requests with optional rejection reason.
Host video call: start/join the in-app WebRTC session for an approved appointment.
Consultation log history with AI-generated summaries per session.
In-Website Video Conferencing (WebRTC)
One-on-one calls only (no multi-party in this phase).
Signaling via Supabase Realtime channel keyed by video_room_id.
Capture session start/end time, duration, and participant count into video_sessions.
Basic screen sharing support.
On call end, persist the transcript (client-side speech-to-text capture or a transcript service) and trigger the summarization Edge Function.
AI Meeting Summarization (BART)
Edge Function generate-summary accepts a transcript, calls the BART model endpoint, and writes the result to appointment_summaries.
Only processes transcripts from ICONSULTA's own video sessions (no external file uploads, per scope).
Show a loading/pending state in the UI while summarization runs; display the final summary on the consultation detail view.
Admin Panel
User Management: CRUD for student/instructor/admin accounts, activate/suspend/archive.
Global dashboard: total, completed, and online consultation counts; system health indicators (DB connected, API running).
Analytics: consultation volume by department/course, attendance rate, completion rate, average session duration.
Report generation: filter by department/date range, export to PDF/Excel.
Notifications overview and system settings.
Notifications
In-app notifications for: request submitted, request approved/rejected, upcoming appointment reminder, summary ready.
Use Supabase Realtime subscriptions so the UI updates live without polling.
NON-FUNCTIONAL REQUIREMENTS
Consultation mode is online-only — do not build in-person scheduling.
No payment/billing functionality.
Mobile-responsive UI (Tailwind breakpoints).
Secure handling of video streams and transcripts; only participants and admins can access a given session's data (enforce via RLS + signed URLs where relevant).
Structure the codebase modularly (feature folders: auth, students, instructors, admin, video, ai-summary, notifications) so other departments/campuses could reuse it later.
